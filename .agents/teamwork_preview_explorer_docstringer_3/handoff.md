## 2. Logic Chain

1. **AST Node Placement Logic**:
   - *Observation*: Tree-sitter tree nodes expose `start_byte` and `end_byte`.
   - *Reasoning*:
     - Python docstrings are statements inside function/class bodies. Placement must occur at the start of the `block` node (after header colon `:`) to form a valid PEP 257 docstring.
     - JS/TS JSDoc comments precede declaration headers. Placement must occur at `node.start_byte` (or wrapping `export_statement.start_byte`).

2. **Indentation Preservation Logic**:
   - *Observation*: Python enforces strict indentation; JS/TS uses leading indentation for code formatting.
   - *Reasoning*:
     - Python body docstrings require indenting equal to `header_indent + 4 spaces` (or matching existing statements in `block`).
     - JS/TS JSDoc comments require indenting equal to the leading whitespace on the target line (`outer_indent`).

3. **Reverse Byte-Offset Edit Ordering Logic**:
   - *Observation*: Inserting text changes UTF-8 byte array length.
   - *Reasoning*:
     - Modifying offset $X$ shifts all offsets $> X$ by $\Delta = \text{length}(R) - (E - S)$.
     - By sorting all target edits in descending order by `start_byte` ($S_1 > S_2 > \dots > S_k$), edits at larger byte offsets are executed first.
     - Edits at smaller byte offsets remain completely undisturbed because modifications occur entirely to their right.

4. **Float List Binary Packing Logic**:
   - *Observation*: `scripts/migrate_vector_store.py` and `scripts/detective.py` both use `struct.pack(f'{len(vector)}f', *vector)`.
   - *Reasoning*:
     - IEEE 754 single-precision float uses 4 bytes per float.
     - `struct.pack('f'*len(v), *v)` and `struct.pack(f'{len(v)}f', *v)` produce identical binary outputs of size `4 * len(v)` bytes.
     - Packed binary `BLOB` storage saves ~80% disk space compared to JSON text array serialization and enables $O(1)$ fast C-level unpacking via `struct.unpack` or `np.frombuffer`.

## 3. Caveats

- **Tree-Sitter Version Variations**: Node names (`block` vs `statement_block`) may vary slightly between specific `tree-sitter-python` or `tree-sitter-javascript` package releases; exact AST field inspection should be verified during parser instantiation.
- **Encoding Assumptions**: Offsets generated by Tree-Sitter correspond to UTF-8 byte offsets, so string indexing in Python must operate on UTF-8 encoded `bytearray` buffers rather than Python character string slices when non-ASCII characters are present.

---

## 4. Conclusion

1. **Python Docstring Insertion**: Insert at the start of the `block` node inside `function_definition` or `class_definition`, with `header_indent + 4 spaces`.
2. **JS/TS JSDoc Insertion**: Prepend at `node.start_byte` (or `export_statement.start_byte`), matching the line's `outer_indent`.
3. **In-Place Modification Order**: Edits must be sorted by `start_byte` in descending order (`reverse=True`) to maintain byte offset alignment.
4. **Vector Persistence**: `struct.pack(f'{len(vector)}f', *vector)` is verified, efficient (4 bytes/float), and fully compatible across SQLite vector tools in the MyOS project.
